What It Does & What It Doesn't

The recommendation-only model is the core design principle, not a limitation.

✓ What It Does

  • Scans a target repository (read-only, allowlisted paths only)
  • Accepts a Blueprint document as the desired state
  • Runs 7 specialist AI agents across quality domains
  • Scores the project across 9 dimensions (0–100)
  • Produces findings with evidence, severity, and recommendations
  • Exports reports as Markdown, HTML, and JSON
  • Masks secrets in all scanned content and output
  • Tracks audit history with per-run comparison

✗ What It Does Not Do

  • Auto-fix any code or configuration
  • Generate step-by-step patch instructions
  • Write, delete, or rename files in a target repository
  • Execute code from an inspected repository
  • Provide authentication (local-only design)
  • Support concurrent audit runs
  • Replace human engineering judgment
  • Access external services during a scan

Audit Workflow

Six steps from project setup to downloadable report.

1

Create a Project

Name the repository you want to audit. The project record provides context for all subsequent audit runs and stores history in PostgreSQL.

2

Upload a Blueprint

Paste or upload any architecture specification, requirements document, or design doc. This becomes the desired state the audit measures against. The blueprint is chunked and indexed via the hybrid RAG pipeline.

3

Scan the Repository

The scanner validates the path against the allowlist, reads all text files (skipping binary and oversized files), classifies them by type, and masks secrets before indexing. The target repository is never modified.

4

Run the Audit

Select mode: rag_only, agent_only, or hybrid. The orchestrator dispatches 6 specialist agents (Architecture, RAG/AI, DevOps, QA, Security, Documentation). Each returns typed findings with evidence and severity. The scoring engine computes 9-dimension scores.

5

Review Findings

The Streamlit UI provides a Findings Dashboard (filter by severity and dimension), a Scores page (per-dimension breakdown), and Audit History for comparing runs over time.

6

Export the Report

Download the full audit report in Markdown (for GitHub / Confluence), HTML (for browser viewing), or JSON (for programmatic processing). The report sanitiser removes any auto-fix content before export.

Audit Dimensions

Every audit scores the project across 9 quality dimensions (0–100 per dimension).

Dimension 01

Architecture

Layer separation, module boundaries, naming patterns, and structural consistency against the blueprint.

Dimension 02

RAG / AI Quality

RAG pipeline design, retrieval strategy, embedding approach, vector store usage, and AI component patterns.

Dimension 03

DevOps / MLOps

CI/CD pipelines, deployment configurations, containerisation, environment management, and release processes.

Dimension 04

Testing / QA

Unit, integration, and E2E test coverage; quality gates; release gate tests; test configuration.

Dimension 05

Security

Credential exposure, unsafe patterns, access controls, secret handling, and path validation.

Dimension 06

Documentation

README completeness, docstrings, architecture docs, ADRs, API documentation, and onboarding guides.

Dimension 07

Observability

Structured logging, Prometheus metrics, distributed tracing readiness, health endpoints, and dashboards.

Dimension 08

Data Management

Schema design, migration strategy, storage patterns, data lifecycle, and backup/recovery considerations.

Dimension 09

Overall Score

Weighted aggregate across all 8 specialist dimensions. Provides a single high-level health indicator.

Safety Boundaries

Seven non-negotiable rules enforced at multiple layers. These are architectural constraints, not configuration options.

Never modify a target repository

E2E test is a mandatory release gate. The system fails CI if any file in a target repository is created, changed, or deleted during an audit.

Never execute target code

The scanner opens files in text mode only. No subprocess calls. No eval. No dynamic import from the target repository.

Never auto-fix findings

The ReportSanitiser removes any auto-fix or patch language from agent output before it reaches the report store or the UI.

Only scan allowed paths

PathValidator checks every audit request against ALLOWED_SCAN_PATHS. Path traversal attempts are resolved and rejected.

Skip binary and oversized files

FileClassifier skips binary assets, compiled artifacts, and files over the configured size limit before any content is read.

Mask secrets in all output

SecretMasker replaces credential patterns (API keys, tokens, passwords) before content is stored or returned in any format.

Never log provider API keys

structlog configuration explicitly excludes LLM provider credentials from all log output, including debug and error levels.
